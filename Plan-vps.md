# Plan-vps.md — VPS (16:00–17:30, `project_plan_24h.md`)

## 0. Контекст

Проект — учебный MVP («ЮрСправочник»). Уровень плана — micro-Plan на одну
фазу «16:00–17:30 VPS» (`project_plan_24h.md`), не на весь проект. Первая
фаза с таким профилем: ИИ-помощник не имеет SSH-доступа к реальному VPS —
предыдущих `Plan-*.md` с этим же ограничением в `docs/archive/` нет
(ближайший образец формата — `docs/archive/Plan-testing.md`, но там ИИ имел
прямой доступ к локальному `uvicorn`). Источник задач — `urok.md`, Фаза 6
(строки 146–160, 9 критериев) и «Формат сдачи» (5-й скриншот, строки 200,
219–220), `spec.md` раздел 7 (способ развёртывания — `nohup`/`disown`,
паттерн `server_summery.md`).

## 1. Статус

Приоритет — текущая активная фаза цикла `spec.md → Plan.md → CLAUDE.md →
Code → Check → README.md`; `spec.md` уже актуализирован (раздел 7 — способ
деплоя, раздел 12 — SSH выполняет пользователь). Секреты нигде не
печатаются в открытом виде — реальный `.env` (уже существует локально, 509
байт) не читается, не цитируется; на VPS создаётся пользователем
самостоятельно по `.env.example`. Источник контекста — `urok.md` Фаза 6,
`spec.md` разделы 7 и 12, `server_summery.md` (вне `project/`, паттерн
`nohup`/логи).

**Границы ответственности — явно, во избежание путаницы:** ИИ-помощник
готовит проверенный список команд, чек-лист проверки и обновляет
документацию по присланным пользователем фактам (вывод команд, логи без
секретов, подтверждение). ИИ-помощник не выполняет SSH-сессию сам и не
видит реальный VPS — каждый шаг с реальным выполнением на сервере помечен
явно, и «Факт выполнения» там заполняет пользователь, не ИИ.

## 1.1 Целевой сценарий

Пользователь на реальном VPS: клонирует репозиторий → создаёт `.venv` →
устанавливает зависимости → создаёт `.env` с реальными значениями (не
коммитит) → запускает приложение в фоне (`nohup`/`disown`) → проверяет, что
оно отвечает и создаёт `data/bot.sqlite3` → смотрит логи (без секретов) →
останавливает и запускает заново без ошибок → делает скриншот работающего
запуска.
