# Plan-readme.md — README (17:30–19:00, `project_plan_24h.md`)

## 0. Контекст

Проект — учебный MVP («ЮрСправочник»). Уровень плана — micro-Plan на одну
фазу «17:30–19:00 README» (`project_plan_24h.md`), не на весь проект, по
тому же паттерну, что предыдущие архивные планы (`docs/archive/Plan-vps.md`
и другие). Источник задач — `project_plan_24h.md`, раздел «17:30–19:00
README» (8 пунктов) и `urok.md`, Фаза 7 (строки 162–180, критерии приёмки
проекта к сдаче). ИИ-помощник не имеет SSH-доступа к реальному VPS
(`CLAUDE.md`, раздел 7) — все факты по деплою уже зафиксированы в
`docs/archive/Plan-vps.md` и переносятся в README оттуда, без повторной
проверки на сервере. Локальные шаги (запуск, `.env`, SQLite, логи) ИИ-помощник
проверяет сам через уже работающий локальный `uvicorn`.

## 1. Статус

Приоритет — текущая активная фаза цикла `spec.md → Plan.md → CLAUDE.md →
Code → Check → README.md`; `spec.md` уже актуализирован по итогам фазы VPS
(раздел 12, раздел 13). Секреты нигде не печатаются в открытом виде —
реальный `.env` не читается и не цитируется ни локально, ни с VPS. Источник

README», `docs/archive/Plan-vps.md` (факты деплоя), `README.md` (уже

## 1.1 Целевой сценарий

Другой человек открывает репозиторий → читает README.md → готовит окружение
(Python, `venv`, зависимости) → создаёт `.env` по `.env.example` и заполняет
реальными значениями → запускает приложение локально → убеждается, что
SQLite создаётся автоматически → смотрит логи → останавливает и запускает
проект заново без ошибок → по краткой спецификации MVP и описанию tools
понимает границы и ограничения ИИ-консультанта → по факту деплоя понимает,
что тот же runtime поднимается и на VPS.
