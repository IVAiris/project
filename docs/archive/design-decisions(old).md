# Design Decisions — ЮрСправочник Chatbot UX/UI

_Зафиксированные решения по эскизам и визуальному стилю всех экранов макета._

## 1. Общая архитектура интерфейса

- Один непрерывный web-экран чата (не многостраничный сайт).
- Три зоны каркаса на каждом экране: шапка (header), лента сообщений (message list), поле ввода (input bar).
- Поле ввода доступно всегда, на всех экранах, а не только в разделе «ИИ-консультант».
- Компоновка меню — **conversational-стиль**: приветствие оформлено как обычное чат-сообщение, кнопки услуг — quick-reply под этим сообщением, не персистентная навигационная панель отдельно от чата.
- Все экраны рисуются в одном контейнере устройства (browser window mockup) одного размера для сопоставимости.
- Лента сообщений может превышать высоту видимой области экрана — это нормально, компенсируется вертикальным скроллом.
- Реплики бота и реплики пользователя визуально смещены относительно друг друга (левое/правое смещение), а не выстроены в одну центральную колонку.
- Кнопки, относящиеся к сообщению, размещаются отдельным блоком НИЖЕ карточки сообщения, с явным вертикальным отступом — не внутри рамки карточки.
- Между всеми блоками (сообщение → кнопки → следующее сообщение) — достаточный воздух (generous spacing), UI не должен выглядеть плотным.

## 2. Цветовая палитра

| Роль | Цвет | HEX |
|---|---|---|
| Фон основной области | Светлый тёплый белый | #F7F4ED |
| Шапка (header) | Тёмный sage | #8FA28A |
| Кнопки — заливка по умолчанию | Светлый sage | #C7D3C0 |
| Контур кнопки при hover / focus (Tab) / active (нажатие) | Приглушённое золото | #C8A96B |
| Текст | Тёмно-серый (charcoal), контрастный на всех фонах палитры | — |

**Правило состояний кнопки:**
- Обычное состояние — заливка #C7D3C0, без контура.
- Hover / Focus (через Tab) / Active (в момент нажатия) — тот же фон, добавляется контур 2px цвета #C8A96B.
- Золото не используется как самостоятельная заливка кнопки — только как индикатор интерактивного состояния.
- Поле ввода (text input) при активном фокусе также получает контур #C8A96B — единообразно с кнопками.

## 3. Типографика

- **Inter** — для интерфейсных элементов и кнопок (лейблы, навигация, CTA).
- **Open Sans** — для основного текста сообщений (реплики бота, описания услуг, FAQ-ответы).
- Текст везде тёмно-серый (charcoal gray) для контраста и читаемости на всех фоновых цветах палитры.

## 4. Экран 1 — Главный экран и хедер (утверждён)

**Хедер** — заливка #8FA28A:
- Слева — заголовок «ЮрСправочник» (кликабелен, работает как home-ссылка на всех экранах).
- Справа — две кнопки: **«FAQ»** и **«Обратная связь»** (заливка #C7D3C0, тёмно-серый текст).

**Тело экрана** (фон #F7F4ED):
1. Приветственное сообщение бота — оформлено как чат-карточка: кто бот, чем помогает (кратко 3 темы), приглашение выбрать услугу или написать вопрос ИИ-консультанту.
2. Под сообщением — quick-reply кнопки с реальными названиями услуг: «Согласование договоров», «152-ФЗ (персональные данные)», «Согласование сделок».
3. Отдельная широкая кнопка **«Перейти к ИИ-консультанту»**.

Все кнопки — одинаковая заливка #C7D3C0, без цветовой иерархии между собой.

**Важное решение:** отдельной видимой кнопки «Оставить заявку» на главном экране нет. Она достижима через «Услуги» и через «ИИ-консультант» (два пути к одному результату).

## 5. Экран «Карточка услуги» и bot-flow оформления заявки (утверждён)

**Карточка услуги** — открывается после выбора конкретной услуги на главном экране:
- Внутри — три таба-кнопки, переключающие содержимое одной и той же карточки: «Регламентный срок», «Ожидаемый результат», «Получить услугу» — активная кнопка выделена золотым контуром #C8A96B.
- Возврат — кнопка «Вернуться на предыдущий экран», присутствует на каждом шаге сценария.

**Bot-flow оформления заявки (пошаговый сценарий, лента чата):**
1. Бот просит описать суть вопроса, с инструкцией про вложение документов (папка «Для юридической службы» на диске P://).
2. Ввод пользователя — с валидацией «не пустой ввод», при ошибке — явное сообщение, без сброса на предыдущий шаг.
3. Бот запрашивает «Как к Вам обращаться?» — валидация не менее 2 символов.
4. Бот запрашивает корпоративную почту — валидация формата email.
5. Финальная сводка: «От: [Контакт: как обращаться | email]», «Тема: [Название услуги]», «Заявка на предоставление консультации по вопросу: [Инпут вопроса]» — кнопки «Вернуться на предыдущий экран», «Уточнить вопрос», «Оставить заявку» (золотой контур как primary-действие).
6. Финальное сообщение: «Ваша заявка направлена в Юридическую службу. Ей присвоен номер [ID заявки]».

**Формат контакта** соответствует формату хранения `"{как обращаться} | {email}"`.

**Порядок полей:** вопрос → имя → email.

**Открытый вопрос:** происхождение инструкции про диск P:\\ — не подтверждено, отмечено для уточнения перед финализацией.

## 6. Экран «ИИ-консультант» (утверждён)

**Вход в экран** — без приветственного сообщения бота. Единственный видимый элемент при входе — активное поле ввода с плейсхолдером «Задайте Ваш вопрос».

**Основной сценарий (happy path):**
- `[Инпут пользователя]` → `[Ответ ИИ-консультанта]` (ответ со ссылкой на текст закона/ЛНА при наличии в базе знаний — правило, фиксируется только текстом сценария, без отдельной отрисовки).
- Кнопки под ответом: «Хочу оставить заявку», «Вернуться на предыдущий экран».

**Ветка «нет ответа»:**
- `[Ответ ИИ-консультанта о том что у него нет ответа, но можно оставить заявку]`.

**Ветка недоступности AI Studio (не блокирует сценарий):**
1. Триггер (комментарий-условие): пользователь задаёт вопрос, но API недоступен/лимит превышен.
2. Сообщение бота: «Сейчас ИИ-консультант временно недоступен. Пожалуйста, воспользуйтесь меню услуг или попробуйте повторить ввод через пару минут.»
3. Кнопки: **«Повторить ввод»**, **«Вернуться на предыдущий экран»**.
4. Аннотация: «История диалога выше сохраняется, не сбрасывается».

**Переход к оформлению заявки:** кнопка «Хочу оставить заявку» ведёт в тот же bot-flow (раздел 5).

**Правила без отдельной отрисовки:** ссылка на закон/ЛНА при цитировании; отказ на вопросы про системные файлы (`.env` и т.п.).

## 7. Экран «FAQ» (утверждён)

**Вход в экран** — по клику на кнопку «FAQ» в хедере, открывается как карточка в текущей ленте чата, без сброса истории.

**Структура — аккордеон:**

1. **3 кнопки-аккордеона по услугам** («Согласование договоров», «152-ФЗ», «Согласование сделок») — единый шаблон полей при разворачивании:
   - Название услуги
   - Сроки предоставления результата
   - Как подать заявку (применительно к конкретной услуге)
   - Что представить для получения услуги

2. **Отдельная кнопка «Правила и контакты»** — свой набор пунктов:
   - Как пользоваться ИИ-консультантом
   - Что делать при ошибках ИИ (со ссылкой на «Обратную связь»)
   - Как подать заявку (общий процесс)

**Осознанное дублирование:** пункт «Как подать заявку» есть и в карточке услуги, и в «Правилах» — принято сознательно.

**Поведение аккордеона:** разворачивание текста поверх экрана (оверлей).

**Навигация:** кнопка «Вернуться на предыдущий экран» — единый паттерн.

## 8. Экран «Обратная связь» (утверждён)

**Вход в экран** — по клику на кнопку «Обратная связь» в хедере, открывается как продолжение текущей ленты чата.

**Три последовательных поля с валидацией** (переиспользуется единый паттерн проверки инпутов):
1. «Как к Вам обращаться» — не менее 2 символов.
2. «Эл. почта» — валидация формата email.
3. «Ваш отзыв» — не пустой ввод.

**Ветка ошибки отправки** (аналогична ветке недоступности AI Studio):
- Сообщение: «Ошибка отправки. Попробуйте повторить ввод через пару минут.»
- Данные не сбрасываются — аннотация «История заполнения на странице сохраняется, не сбрасывается».
- Кнопка «Отправить» становится активной повторно.

**Успешное завершение:** «Ваш отзыв направлен и будет рассмотрен.»

**Навигация:** кнопка «Вернуться на предыдущий экран».

## 9. Инструменты

- Эскизы отрисовываются вручную в draw.io (app.diagrams.net).
- Библиотека фигур: встроенный набор **Mockups** (More Shapes → Mockups + Mockup Containers) для рамок браузера/устройства, кнопок, полей ввода (Text Input).
- Чат-пузыри сообщений — Rounded Rectangle с левым/правым смещением для разграничения бота и пользователя.
- Внешний контейнер экрана — `mxgraph.mockup.containers.browserWindow`, единый для всех страниц макета.
- Референсные PNG-мокапы используются как визуальный ориентир по цвету и стилю, не как финальный экспортируемый макет.
