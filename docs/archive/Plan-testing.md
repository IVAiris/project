# Plan-testing.md — Тестирование (14:00–16:00, `project_plan_24h.md`)

## 0. Контекст

Проект — учебный MVP («ЮрСправочник»). Уровень плана — micro-Plan на одну
фазу «14:00–16:00 Тестирование» (`project_plan_24h.md`), не на весь проект.
Предыдущие закрытые планы — в `docs/archive/` (`Plan-runtime.md`,
`Plan-sqlite.md`, `Plan-bot-flow.md`, `Plan-web-ui.md`, `Plan-tools.md`,
`Plan-ai-scenarios.md`) — не активны, используются как образец формата и
источник уже установленных решений (паттерн изоляции тестовой БД, паттерн
согласования живых вызовов API). Источник задач для этого плана —
`project_plan_24h.md` (чек-лист раздела «14:00–16:00 Тестирование», уже
актуализирован — 6 из 10 пунктов перенесены в `[x]`) и Фаза 5 `urok.md`
(строки 130–144, 200–221 — точные критерии приёмки и формат скриншотов).

## 1. Статус

Приоритет — текущая активная фаза цикла `spec.md → Plan.md → CLAUDE.md →
Code → Check → README.md`; `spec.md` уже актуализирован (раздел 11 — решение
по объёму `knowledge/` явно вынесено в Шаг 2 этого плана). Секреты нигде не
печатаются в открытом виде — только ссылки на `.env`/`os.getenv`. Источник
контекста — `project_plan_24h.md`, `spec.md` раздел 11, `urok.md` Фаза 5;
документ `docs/archive/Plan-ai-scenarios.md`, Шаги 5.1, 7.1, 10.1 (известная
нестабильность `MAX_STEPS`, паттерн изоляции сессий, два реальных инцидента
с потерей `data/bot.sqlite3`); документ `docs/archive/Plan-tools.md`, Шаг 2
(уже пройденный unit-тест защиты `.env`).

## 1.1 Целевой сценарий

Сотрудник компании в реальном браузере: (а) задаёт вопрос по базе знаний —
получает содержательный ответ; (б) задаёт вопрос про данные, которых в
`knowledge/` нет (например, скидку или гарантию) — получает честный отказ,
не выдумку; (в) просит показать/прочитать `.env` или файл вне `knowledge/` —
получает отказ без утечки содержимого; (г) нажимает «Хочу оставить заявку» —
видит подготовленный черновик. Каждая ветка — отдельный реальный диалог с
живой моделью, не синтетический тест.
