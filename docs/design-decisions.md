# design-decisions.md — ЮрСправочник Design System

## 1. Назначение и границы

`design-decisions.md` — визуальный контракт проекта чат-бота юридической службы «ЮрСправочник».

Применяется ко всем экранам продукта:
- главный экран (приветствие + выбор услуги);
- карточка услуги и bot-flow оформления заявки;
- экран «ИИ-консультант»;
- экран «FAQ»;
- экран «Обратная связь».

Документ регулирует только дизайн-слой: токены, типографику, компоненты, состояния,
макет. Он не описывает бизнес-логику, сценарии валидации по сути (см. `bot-ux-flow.md`)
и серверные проверки.

## 2. Визуальное направление

ЮрСправочник — сдержанный, спокойный корпоративный чат-интерфейс. Формат — единая
лента диалога (conversational UI), а не многостраничный сайт с классической навигацией.

Характер интерфейса:
- Светлый тёплый фон, приглушённый sage как основной брендовый цвет шапки.
- Золото используется дозированно — только как индикатор интерактивного состояния
  (hover/focus/active), не как самостоятельная заливка.
- Один общий шрифтовой стиль для интерфейса, отдельный — для основного текста сообщений.
- Приоритет: читаемость, понятные шаги диалога, видимые состояния кнопок и полей.

## 3. Технологии

Зафиксирован в `docs/archive/Plan-web-ui.md` §2 «Требования к результату» (решено 2026-08-30):
FastAPI (backend) + статические HTML/CSS/JS без фреймворка (frontend), без
дополнительных зависимостей сверх `requirements.txt`.

Общее правило: все повторяющиеся значения (цвет, отступ, радиус) реализуются через
общие токены, без произвольных hex-значений и случайных радиусов/отступов в компонентах.

## 4. Токены

### 4.1. Цвета

| Токен | Значение | Роль |
|---|---:|---|
| `--jr-sage` | `#8FA28A` | Основной брендовый цвет, заливка шапки |
| `--jr-sage-light` | `#C7D3C0` | Заливка кнопок по умолчанию (обычное состояние) |
| `--jr-gold` | `#C8A96B` | Акцент состояния: контур hover/focus/active у кнопок и полей ввода |
| `--jr-cream` | `#F7F4ED` | Основной фон приложения |
| `--jr-ink` | `#3A3A3A` | Основной текст (тёмно-серый, charcoal), контрастный на всех фонах палитры |
| `--jr-surface` | `#FFFFFF` | Поверхность карточек сообщений на фоне `--jr-cream` |
| `--jr-text-muted` | `#8A8A8A` | Вторичный текст: плейсхолдеры, комментарии-условия, аннотации |
| `--jr-border` | `#D9D3C7` | Базовая граница элементов |
| `--jr-danger` | `#A84242` | Ошибка валидации, сообщение о недоступности сервиса |

### 4.2. Правила использования цветов

- `--jr-cream` — фон всех экранов без исключения.
- `--jr-surface` — заливка карточек-сообщений бота и пользователя (белая или чуть светлее фона).
- `--jr-sage` — используется только в шапке; не применяется как заливка кнопок.
- `--jr-sage-light` — единственная заливка кнопок в обычном состоянии; кнопки не имеют
  цветовой иерархии между собой (нет отдельного «primary» цвета заливки).
- `--jr-gold` — не используется как заливка; только как контур 2px в интерактивных состояниях.
- Цвет не является единственным способом передать ошибку или состояние — всегда
  сопровождается текстом сообщения.

### 4.3. Типографика

| Роль | Шрифт | Правило |
|---|---|---|
| Интерфейсные элементы, кнопки, лейблы, навигация | Inter | Для всех интерактивных элементов интерфейса |
| Основной текст сообщений | Open Sans | Для реплик бота, описаний услуг, FAQ, аннотаций |

Рекомендуемая шкала:
- Заголовок карточки/секции: 18–20px, 600, line-height 1.3.
- Основной текст сообщения: 15–16px, 400, line-height 1.5.
- UI/лейбл/кнопка: 14–15px, 500–600.
- Плейсхолдер/аннотация/метаданные: 12–13px, 400, `--jr-text-muted`.

Не использовать более двух шрифтовых семейств.

### 4.4. Отступы

Базовая шкала (по пропорциям эскизов):
- `space-1`: 4px
- `space-2`: 8px
- `space-3`: 12px
- `space-4`: 16px
- `space-6`: 24px
- `space-8`: 32px
- `space-10`: 40px

Правила:
- Внутренний отступ полей и кнопок: 12–16px.
- Внутренний отступ карточки-сообщения: 16–24px.
- Между карточкой сообщения и её кнопками (кнопки — отдельный блок, не внутри рамки): 16px.
- Между смысловыми блоками ленты (сообщение → кнопки → следующее сообщение): 24–32px.
- Не применять произвольные интервалы, если значение есть в шкале.

### 4.5. Границы и радиусы

- Базовая граница: 1px solid `--jr-border`.
- Активная граница (hover/focus/active): 2px solid `--jr-gold`.
- **Радиус — единый для всех элементов интерфейса: 12px** (карточки-сообщения, кнопки,
  поля ввода, аккордеон FAQ). Скругление кнопок и полей ввода равно скруглению
  прямоугольников карточек — отдельного, более сильного радиуса для кнопок не применяется.
- Тень: минимальная или отсутствует; визуальное разделение строится на фоне, границе
  и отступах, как на текущих эскизах.

## 5. Макет

### 5.1. Структура

- Экран строится из трёх зон: шапка, лента сообщений, поле ввода.
- Desktop-контейнер — фиксированная ширина окна браузера (как на эскизах), с равномерными
  внутренними полями.
- Лента сообщений может превышать высоту видимой области — компенсируется вертикальным
  скроллом внутри окна, без сжатия контента.
- Реплики бота и реплики пользователя смещены относительно друг друга (левое/правое
  смещение), не выстроены в одну центральную колонку.

### 5.2. Иерархия

- На каждом экране кнопки не имеют цветовой иерархии между собой (нет выделенного primary
  по заливке) — выделение текущего/активного действия происходит только через золотой
  контур состояния (hover/focus/active).
- Опасные/предупреждающие сообщения (ошибка валидации, недоступность сервиса) выделяются
  цветом текста `--jr-danger`, не заливкой всей карточки.

## 6. Компоненты

### 6.1. Шапка

- Заливка `--jr-sage`.
- Слева — название бота (кликабельно, ведёт на главный экран, действует на всех страницах).
- Справа — две кнопки: «FAQ» и «Обратная связь», заливка `--jr-sage-light`, текст `--jr-ink`.

### 6.2. Кнопки

Единый визуальный тип кнопки для всего интерфейса — без вариантов Primary/Secondary/Danger
по заливке (открытый вопрос, см. раздел 8).

| Состояние | Заливка | Контур | Текст |
|---|---|---|---|
| Default | `--jr-sage-light` | нет | `--jr-ink`, контраст ≥ 80% |
| Hover / Focus-visible / Active | `--jr-sage-light` | 2px `--jr-gold` | `--jr-ink`, контраст ≥ 80% |
| Disabled / Loading | `--jr-sage-light` | нет | `--jr-ink` с непрозрачностью ~50% (вполовину бледнее), контраст ≥ 60% |

Правила:
- Радиус кнопки — 12px, равен радиусу карточек (см. 4.5).
- В состоянии loading повторная отправка недоступна.
- Текст кнопки описывает действие явно: «Оставить заявку», «Отправить вопрос», а не
  обобщённое «Продолжить».

### 6.3. Поля ввода

- Заливка: `--jr-surface` (`#FFFFFF`) — единая для всех полей ввода на всех экранах,
  включая строку ввода на экране «ИИ-консультант».
- Обычное состояние: граница 1px `--jr-border`, плейсхолдер `--jr-text-muted`.
- Активный фокус: контур 2px `--jr-gold` — тот же принцип, что у кнопок.
- Disabled: заливка `--jr-cream` (#F7F4ED, сливается с фоном страницы), граница
  `--jr-border` без изменений, текст/плейсхолдер `--jr-text-muted` с непрозрачностью
  ~50% (контраст ≥60%, тот же принцип, что у кнопок в разделе 6.2).
- Радиус — 12px, единый с остальными элементами.
- Валидация: ошибка отображается текстом рядом с полем, цвет `--jr-danger`; при ошибке
  ввод не отправляется, но сохраняется, и доступен возврат на предыдущий шаг.

### 6.4. Карточки-сообщения

- Заливка `--jr-surface` на фоне `--jr-cream`.
- Радиус — 12px, единый с кнопками и полями ввода.
- Кнопки, относящиеся к сообщению, размещаются отдельным блоком ниже карточки,
  с отступом 16px — никогда внутри рамки карточки.
- Карточка пользователя визуально смещена вправо, карточка бота — влево (см. 5.1).

### 6.5. Аккордеон (экран FAQ)

- Заголовок раздела — кнопка того же визуального типа, что и остальные кнопки интерфейса.
- Развёрнутый текст — оверлей поверх экрана (зафиксировано на эскизе).
- Радиус — 12px, единый с остальными компонентами.

### 6.6. Аннотации и комментарии-условия

- Курсив, цвет `--jr-text-muted`, размер 12–13px.
- Используются для обозначения технических условий («если проверка не прошла…»)
  и служебных пояснений («история диалога сохраняется, не сбрасывается»),
  не являются репликами бота.

## 7. Обязательные состояния

Все интерактивные элементы (кнопки, поля ввода):
- default;
- hover;
- focus-visible;
- active;
- disabled;
- loading.

Правило контраста текста:
- Во всех состояниях, кроме disabled/loading — контраст текста к фону не менее 80%.
- В состоянии disabled/loading — не менее 60% (текст вполовину бледнее обычного).

Экраны с асинхронными действиями (отправка заявки, отправка отзыва, запрос к ИИ-консультанту)
предусматривают отдельную ветку ошибки с сохранением введённых данных и возможностью
повторить действие — зафиксировано в сценариях bot-flow заявки, ИИ-консультанта и
«Обратной связи».

## 8. Открытые вопросы (закрыто 2026-08-30)

- **Иерархия кнопок** — решено: принцип равноправия сохраняется и для будущих
  экранов — избегать выделенного «primary»-цвета, если явно не потребуется акцентировать
  одно ключевое действие среди нескольких (например, «Оставить заявку» в финальной сводке
  уже выделяется золотым контуром как единственное активное состояние на этом шаге).
- **Danger-состояние кнопки** — решено: для явно разрушительных действий (если такие
  появятся, например «Отменить заявку») вводится отдельный вариант с контуром/текстом
  `--jr-danger`, по аналогии с текстом ошибки валидации.
- **Технологический стек** — решено, зафиксирован в `docs/archive/Plan-web-ui.md` §2 «Требования
  к результату»: FastAPI (backend) + статические HTML/CSS/JS без фреймворка (frontend),
  без дополнительных зависимостей сверх `requirements.txt`. Плейсхолдер в разделе 3 снят.
- **Focus-visible при клавиатурной навигации без мыши** — решено: тот же золотой контур,
  что и для hover, без отдельного визуального языка — для единообразия и снижения
  количества правил.

## 9. Запреты

Запрещено без отдельного согласования:
- Вводить второй акцентный цвет вне палитры (`--jr-sage`, `--jr-sage-light`, `--jr-gold`).
- Использовать золото как заливку большой площади или для длинного текста.
- Делать разный радиус скругления у кнопок, полей ввода и карточек — радиус единый (12px).
- Размещать кнопки внутри рамки карточки-сообщения.
- Создавать несколько конкурирующих равноправных «главных» действий на одном шаге сценария,
  кроме случаев, где это осознанно предусмотрено сценарием (сводка заявки — все три кнопки
  равноправны по смыслу).
- Терять введённые пользователем данные при ошибке отправки (валидация, недоступность
  ИИ-консультанта, ошибка отправки отзыва).

## 10. Проверка перед сдачей

- Цвета, типографика, отступы и единый радиус (12px) соответствуют токенам.
- У всех кнопок и полей ввода — согласованные состояния: default, hover, focus, active,
  disabled, loading, с контрастом ≥ 80% (или ≥ 60% в disabled/loading).
- Кнопки — отдельный блок ниже карточки сообщения, не внутри неё.
- Реплики бота и пользователя визуально различимы по смещению (лево/право).
- Ветки ошибок (валидация, недоступность ИИ, ошибка отправки) сохраняют введённые данные
  и предлагают повтор действия.
- Все 5 экранов (главный, карточка услуги + заявка, ИИ-консультант, FAQ, обратная связь)
  соответствуют этому документу.
