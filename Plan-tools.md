## 1.1 Целевой сценарий

Не пользовательский сценарий (эта фаза не трогает UI), а сценарий разработчика,
проверяющего готовность tools к следующей фазе:
1. Разработчик из Python-консоли или self-test вызывает
   `agent.tools.search_knowledge("форс-мажор")` — получает список совпадений
   с указанием файла.
2. Вызывает `agent.tools.read_knowledge_file("services.md")` — получает
   полный текст; на `read_knowledge_file("../.env")` получает явный отказ,
   не содержимое `.env`.
3. Вызывает `agent.tools.prepare_lead_draft(session, ...)` — черновик
   появляется в `session["lead_draft"]` без `contact`.
4. Добавляет `contact` в `session["lead_draft"]` вручную (эмулируя будущий
   под-шаг) и вызывает `agent.tools.save_confirmed_lead(session_id, session)`
   — в `leads` появляется ровно одна строка с `source="ai_consultant"`;
   повторный вызов не создаёт вторую строку.
5. Запускает `python agent_runtime.py` с тестовым вопросом — видит в логе
   `[tool] selected: search_knowledge` и финальный ответ модели.

## 2. Требования к результату

**Результат фазы:** рабочий `agent/tools.py` с четырьмя функциями и их
whitelist-проверками; `agent_runtime.py` умеет прокидывать `session_id`/
`session` в `call_tool`; `agent/soul.md` и `CLAUDE.md` синхронизированы с
решениями раздела 1.

**Явно НЕ входит в эту фазу** (граница со следующей фазой «AI-сценарии»):
- подключение `app.py` к `agent_runtime.run_agent` (нет нового режима
  сессии типа `ai_consultant` в `app.py`);
- реализация структурного под-шага сбора `contact` в UI/`app.py`
  (используется в следующей фазе, здесь только контракт данных);
- изменение `bot_flow.py` (только чтение/переиспользование
  `get_service_card` для валидации `service`, без правок самого файла);
- изменение схемы SQLite (`leads`/`feedback` не меняются).

**Файлы, разрешённые к изменению в этой фазе:**
- `project/CLAUDE.md`
- `project/agent/tools.py` (новый файл)
- `project/agent/soul.md`
- `project/agent_runtime.py`
- `project/project_plan_24h.md` (только чек-лист фазы, в конце)
- `project/Plan-tools.md` (этот файл — статус/факт по ходу работы)

**Снимок контракта данных (источник истины — `spec.md`, раздел 5, не
дублируется здесь дословно, только используемые в этой фазе поля):**
- `search_knowledge(query: str) -> list[{"file": str, "excerpt": str}]`
- `read_knowledge_file(filename: str) -> {"file": str, "content": str}`,
  whitelist `{"services.md", "faq.md", "rules.md"}` — двухслойная проверка
  пути по паттерну `agent-py.md` (синтаксис строки, затем `resolve()`/
  `relative_to()` против `KNOWLEDGE_DIR`), затем точное совпадение итогового
  имени файла с whitelist (см. Шаг 2).
- `prepare_lead_draft(session, service, problem_text, agent_summary, missing_info) -> dict`
  — пишет в `session["lead_draft"]`, `contact` изначально `None`.
- `save_confirmed_lead(session_id, session) -> {"lead_id": int} | {"already_sent": True}`
  — не tool модели; читает/очищает `session["lead_draft"]`, вызывает
  `db.insert_lead(source="ai_consultant", ...)`.
- `call_tool(name, arguments, session_id, session)` / `run_agent(..., session_id, session)`
  — новые параметры в `agent_runtime.py`.
- `KNOWN_TOOLS` в `agent_runtime.py` для диспетчеризации моделью: `{"search_knowledge", "read_knowledge_file", "prepare_lead_draft"}` — `save_confirmed_lead` исключён.

**Локальный разделяемый ресурс:** новых БД/портов/файлов `.env` эта фаза не
создаёт — `data/bot.sqlite3` уже существует и используется как есть (только
через уже готовый `db.insert_lead`).

  реализационных деталей.

  парсится моделью и что под черновиком есть 3 конкретные кнопки.
