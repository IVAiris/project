Тип проекта: учебный (24-часовой MVP «ЮрСправочник»). Уровень плана: **micro** — покрывает одну фазу из `project_plan_24h.md` («1:30–3:00 SQLite»), не весь проект.

## 1. Статус

Приоритет: высокий — блокирует Web UI и tools (`prepare_lead_draft`/`save_confirmed_lead` пишут в эту схему). Текущее состояние: не начато, файла `data/` и `db.py` в репозитории нет. Секреты в этой фазе не участвуют (SQLite без пароля/сети) — правило `sensitive-data` не задействовано. Источник контекста: `spec.md` (раздел 5, актуализирован сегодня), `CLAUDE.md` (раздел 4 — пути `PROJECT_ROOT`-относительные, `.gitignore`), `urok.md` (Фаза 2, критерии приёмки).

## 1.1 Целевой сценарий

Разработчик (ведущий эту фазу) запускает `python db.py` локально → модуль создаёт папку `data/` и файл `data/bot.sqlite3`, если их нет → создаёт таблицы `leads`/`feedback`, если их нет → self-test вставляет одну тестовую заявку (`source="bot_flow"`) и одну тестовую обратную связь → читает обе записи обратно и печатает их количество и вычисленный `status` → разработчик видит в stdout, что данные сохранились и таблицы независимы друг от друга, без запуска Web UI или AI-сценария.

## 4. Прямые зависимости и проверки

- Источник истины по схеме данных: `spec.md`, раздел 5 (не дублируется в коде комментариями сверх необходимого).
- Источник истины по путям (`PROJECT_ROOT`-относительные): `CLAUDE.md`, раздел 4; образец — `ai_client.py`.
- Источник истины по UX-полям (`contact_name` ≥2 символа, email-формат, `contact`-разделитель): `docs/bot-ux-flow.md`, разделы 5 и 8 — валидация этих правил не входит в эту фазу, только имена/типы колонок.
- Порядок зависимостей: `insert_lead`/`insert_feedback` не зависят от `agent_runtime.py`/`ai_client.py`; следующая фаза (`bot_flow.py`) зависит от готового `db.py`.
- Типовая ошибка всей фазы: смешать вычисление `status`/`created_at` с ответственностью вызывающего кода — обе величины должны формироваться исключительно внутри `db.py`, чтобы избежать рассинхронизации между bot-flow и будущими `agent/tools.py`.
- **Контракт соединений (зафиксировано 2026-08-30, действует для всех следующих фаз, использующих `db.py`):** каждая публичная функция (`init_db`, `insert_lead`, `insert_feedback`) сама открывает и закрывает соединение через `get_connection(db_path=DB_PATH)` — соединение никогда не кэшируется на уровне модуля и не передаётся как аргумент извне. Причина: единственный процесс FastAPI+uvicorn (`spec.md`, раздел 7) будет вызывать эти функции из threadpool на будущих HTTP-роутах, а `sqlite3` по умолчанию не переживает передачу одного соединения между потоками (`check_same_thread=True`). `agent/tools.py` и `bot_flow.py` в следующих фазах обязаны вызывать `insert_lead`/`insert_feedback` напрямую с данными — не открывать свои соединения и не оборачивать эти функции в собственный connection-менеджмент.
- **История диалога не пересекается с этой фазой:** `db.py` вызывается только при уже подготовленном черновике (`save_confirmed_lead`) или в bot-flow без ИИ — сценарий недоступности AI Studio (`spec.md`, раздел 6; `docs/bot-ux-flow.md`, раздел 10) обрабатывается до вызова `db.py` и не требует изменений в этом модуле.
- **Конкурентный доступ проверен явно (уточнение 2026-08-30 — сервисом пользуются одновременно разные сотрудники, включая одновременное создание записей).** Тест: 30 потоков параллельно вызывают `insert_lead` на одном файле БД — 30/30 успешно, `id` уникальны, строк в таблице ровно 30, 0 ошибок. Второй тест: 60+60 параллельных `insert_lead`/`insert_feedback` вперемешку — 120/120 успешно за 0.79 сек, 0 ошибок, 0 потерь. Работает благодаря контракту соединений выше (новое соединение на вызов, не общее на процесс) и дефолтному `timeout=5.0` сек у `sqlite3.connect()` — конкурентные писатели ждут освобождения файловой блокировки вместо немедленного `database is locked`. Зафиксировано в `spec.md`, раздел 6.
