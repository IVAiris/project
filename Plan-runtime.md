# Plan-runtime.md — Фаза «Основа runtime»

## 0. Контекст

Тип проекта: учебный (24-часовой MVP «ЮрСправочник»). Уровень плана: **micro** — покрывает одну фазу из `project_plan_24h.md` («3:00–4:30 Основа runtime»), не весь проект.

**Предыдущий слой:** спецификация (`spec.md`) и база знаний (`README.md`, `knowledge/services.md`, `faq.md`, `rules.md`) — уже написаны, выверены на соответствие `urok.md` и закоммичены в git.

**Следующий слой:** «Безопасные tools» (4:30–6:00, `project_plan_24h.md`) — реализация `agent/tools.py` (`search_knowledge`, `read_knowledge_file`, `prepare_lead_draft`, `save_confirmed_lead`). Этот план сознательно не реализует сами tools — только точку их вызова (`call_tool`) как заглушку.

## 1. Статус

Приоритет: высокий — блокирует все последующие AI-сценарии. Текущее состояние: не начато, `.env` с реальным ключом уже создан и проверен (`test_connection.py` успешно вызвал модель). Секреты не печатаются в открытом виде — только ссылка на `.env`/`.env.example` (см. `sensitive-data`). Источник контекста: `spec.md` (разделы 5–7), `urok.md` (Фаза 3), `agent-py.md`, `ai_studio_api_notes.md`.

## 1.1 Целевой сценарий

Разработчик (не конечный пользователь бота, а тот, кто ведёт эту фазу) запускает `agent_runtime.py` локально с тестовым сообщением → runtime вызывает модель через `ai_client.py` → если модель вызывает инструмент, runtime логирует шаг, вызывает заглушку `call_tool` (пока без реальных tools) → runtime возвращает финальный ответ модели или контролируемое сообщение об остановке по `MAX_STEPS` → всё это видно в логе шагов.

## 2. Требования к результату

**Что должно получиться:** `ai_client.py`, `agent/soul.md`, `agent_runtime.py` в `BOT/project/`; лимит шагов и логирование; проверенный биллинг AI Studio.

**Явные ограничения (что не делаем в этом плане):**
- Не реализуем сами функции tools (`search_knowledge` и т.д.) — это следующий слой.
- Не подключаем FastAPI/HTTP-роуты — это ещё позже (Web UI, 10:00–13:00).
- Не трогаем `knowledge/`, `README.md`, `spec.md`.

**Файлы, разрешённые к изменению:** `BOT/project/ai_client.py` (новый), `BOT/project/agent/soul.md` (новый), `BOT/project/agent/__init__.py` (новый, пустой, чтобы `agent` был пакетом), `BOT/project/agent_runtime.py` (новый). Существующие файлы не редактируются.

**Снимок контракта данных (env vars, из `.env.example`, уже зафиксировано — не переопределяется здесь):**
`YANDEX_API_KEY`, `YANDEX_FOLDER_ID`, `YANDEX_MODEL_URI` (полный `gpt://{folder}/{model}`), `YANDEX_BASE_URL`, `YANDEX_TEMPERATURE` (float, дефолт `0.4`), `YANDEX_MAX_TOKENS` (int, дефолт `10000`).

**Снимок контракта вызова модели (из `ai_studio_api_notes.md`, не переопределяется — только используется):**
- Метод: `client.chat.completions.create(model=..., messages=[...], tools=[...], tool_choice="auto")`.
- Возвращаемое значение — **полное сообщение** (`response.choices[0].message`), а не только `.content`, чтобы runtime видел `.tool_calls`.
- `message.tool_calls[i].function.name` / `.function.arguments` (JSON-строка) — контракт для парсинга вызова инструмента.
- Результат инструмента возвращается модели как `{"role": "tool", "tool_call_id": tool_call.id, "content": <JSON-строка результата>}`.

**Снимок контракта сессии (из `spec.md`, раздел 5, не переопределяется):**
`sessions[session_id] = {"messages": [...], "mode": "bot_flow" | "ai_consultant", "flow_state": ..., "lead_draft": None}` — этот план создаёт структуру данных и загрузку истории в память, но не сам HTTP-слой, который её создаёт (это Web UI фаза).

**`MAX_STEPS = 6`** — зафиксировано дословно в `agent-py.md:924`, не открытый вопрос.

## 4. Прямые зависимости и проверки

- Источник истины по env-переменным: `.env.example` (не дублируется здесь).
- Источник истины по методу вызова модели: `ai_studio_api_notes.md`.
- Источник истины по паттерну loop/`MAX_STEPS`/`call_tool`: `agent-py.md` (терминальный урок).
- Источник истины по ограничениям консультанта: `knowledge/rules.md`.
- Порядок зависимостей: `agent/soul.md` не зависит от кода и может писаться параллельно с `ai_client.py`; `agent_runtime.py` зависит от готового `ai_client.py` (импортирует функцию вызова модели).
- **Направление импорта между фазами:** `ToolError` определяется в `agent_runtime.py` (эта фаза); `agent/tools.py` (следующая фаза) импортирует `ToolError` оттуда и определяет свой `TOOL_DEFINITIONS` — не наоборот. Несоблюдение этого направления в следующей фазе создаст кольцевой импорт.
- **Ограничение тестируемости этой фазы:** без `TOOL_DEFINITIONS` (следующая фаза) модель не может вернуть `tool_calls` — раздел кода `call_tool`/`ToolError` в этой фазе останется написанным, но не проверенным живым вызовом. Это не дефект этой фазы, а ожидаемое следствие порядка фаз в `project_plan_24h.md`.
- Типовая ошибка всей фазы: спутать `chat.completions.create` с `responses.create` (уже разобрано и закрыто в `ai_studio_api_notes.md` — не повторять).
