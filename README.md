## О проекте

**ЮрСправочник** — внутренний веб-чат с ИИ-консультантом по базе знаний юридического департамента компании. Бот помогает сотрудникам быстро находить ответы на типовые вопросы, готовить черновики обращений по утверждённым шаблонам и передавать вопрос юристу, если типового ответа недостаточно.

### Для кого бот и какую задачу решает

Бот предназначен для сотрудников компании, которым нужна быстрая консультация по внутренним юридическим регламентам без прямого обращения к юристу. Задача бота — сократить количество простых повторяющихся вопросов, которые сейчас решаются вручную, и оставить юристу только те случаи, где типового ответа действительно нет.

### Каталог услуг

| № | Услуга                                 | Содержание (по вашим уточнениям)                                                                               |
| - | -------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 1 | Консультация о порядке согласования договоров | Порядок согласования договора в компании, обязательные (существенные) условия, которые должны быть в документе |
| 2 | Консультация об обработке персональных данных (по 152-ФЗ) | Разъяснения по применимому закону (что он требует) в понятной формулировке |
| 3 | Получение корпоративного одобрения сделки | Когда сделка подлежит согласованию по корпоративным документам, что готовить для принятия решения |

### FAQ — категории

1. Услуги — что делает бот и чем он может помочь.
2. SLA, сроки и приоритет обращения (внутренний сервис, без оплаты сотрудником).
3. Формат работы — в каком канале доступен бот, что он делает и не делает.
4. Правила и контакты — что бот не делает, как связаться с юристом напрямую.

### Логика меню и навигация

Бот обслуживает пять режимов: **Услуги**, **FAQ**, **Оставить заявку**, **ИИ-консультант**, **Обратная связь** (`urok.md`: «Пользователь должен видеть главное меню, выбирать Услуги, FAQ, Оставить заявку, ИИ-консультант, Обратная связь и вводить текстовые сообщения»). По утверждённому макету они не выведены как пять равноценных кнопок одного меню: **FAQ** и **Обратная связь** — кнопки в хедере (видны на любом экране), **Услуги** и **ИИ-консультант** — элементы тела главного экрана, **Оставить заявку** отдельной кнопки не имеет и достигается через карточку услуги или через ИИ-консультанта. Подробное описание каждого экрана, порядок шагов и UX-решения — источник истины `docs/bot-ux-flow.md`, не дублируется здесь.

Каталог услуг (`knowledge/services.md`) описывает предметные юридические направления работы, а не технические функции бота — bot-flow и ИИ-консультант — это универсальный слой доставки, одинаково применимый к любой из трёх услуг.

### Разница между bot-flow и ИИ-консультантом

- **Обычный bot-flow** — предсказуемый кнопочный сценарий без обращения к модели: просмотр услуг, FAQ, заполнение и сохранение обычной заявки, отправка обратной связи. Работает даже если AI Studio API недоступен.
- **ИИ-консультант** — отдельный сценарий, отвечающий только по материалам `knowledge/`. Помогает выбрать услугу, задаёт 1–2 уточняющих вопроса, готовит структурированный черновик заявки. Не является свободным чатом на произвольные темы.

### Данные, которые собираются для заявки

Номер заявки (`id`, сообщается пользователю в финальном сообщении), услуга, краткое описание задачи, контакт, который пользователь оставляет сам, статус обращения, дата создания.

### Данные, которые бот не должен запрашивать

Персональные данные сверх необходимого контакта (паспортные данные, финансовую информацию, содержание `.env` и системные секреты), а также любые сведения, не относящиеся к оформлению обращения.

### Ограничения ИИ-консультанта

- Отвечает только по материалам `knowledge/`, не выдумывает цены, сроки, скидки и гарантии.
- Если информации нет — честно сообщает об этом и предлагает оставить заявку.
- Не выполняет shell-команды, не читает `.env` и файлы вне `knowledge/`.
- Не сохраняет заявку без явного подтверждения пользователя.

### Границы MVP

Не входит: домен, публичная ссылка на интерфейс, отдельный кабинет управления, внешний production-контур.

### План реализации по слоям

- **Interface** — `static/index.html`/`style.css`/`script.js` (без фреймворка), стилизовано по `docs/design-decisions.md`: главное меню, поле свободного текстового ввода, история сообщений в рамках сессии (подробности экранов и логики — `docs/bot-ux-flow.md`).
- **Backend** — один Python runtime (FastAPI + uvicorn), `app.py` — единая точка запуска и эндпоинт `POST /api/chat`; `bot_flow.py` — обычный сценарий (каталог услуг, FAQ, заявка, обратная связь) без обращения к модели. ИИ-консультант подключён к `agent_runtime.py` — свободный чат по базе знаний, эскалация («Хочу оставить заявку»), сбор контакта и сохранение заявки с `source="ai_consultant"` (фаза «AI-сценарии», `docs/archive/Plan-ai-scenarios.md`, закрыта и проверена реальным сквозным прогоном).
- **Database** — `db.py`, SQLite (`data/bot.sqlite3`, автосоздание при старте), таблицы `leads` и `feedback` с различимым `source` (`bot_flow` / `ai_consultant`).
- **Agent** — `ai_client.py`, `agent_runtime.py`, `agent/tools.py` (`search_knowledge`, `read_knowledge_file`, `prepare_lead_draft`, `save_confirmed_lead`), `agent/soul.md`.

### Подготовка окружения

Целевая ветка — Python 3.13.x (см. `spec.md`, раздел 13). На реальной VPS (Ubuntu 24.04) Python 3.13 недоступен из официальных репозиториев `apt` — только 3.12 и 3.11; получить 3.13 можно было бы лишь через сторонний репозиторий `deadsnakes PPA`, что решено не делать (лишняя зависимость от внешнего источника пакетов ради минимального технического риска). Проект проверен и работает на Python 3.12 (подтверждено реальным деплоем — `docs/archive/Plan-vps.md`, Шаг 3), так как все зависимости требуют только `>=3.10`, а код не использует синтаксис, специфичный для 3.11+/3.12+/3.13. Из корня `project/`:

**macOS/Linux:**
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

**Windows (PowerShell):**
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### Настройка `.env`

Скопируйте шаблон и заполните реальными значениями (файл не коммитится):
```bash
cp .env.example .env
```
Список переменных и их назначение — в `.env.example`.

### Запуск приложения

```bash
uvicorn app:app --reload
```
Приложение слушает `http://127.0.0.1:8000/` (порт задаётся дефолтом uvicorn, в коде не переопределён).

### SQLite

Инициализация полностью автоматическая: `db.init_db()` вызывается при каждом старте приложения и создаёт `data/bot.sqlite3` с таблицами `leads`/`feedback` (`CREATE TABLE IF NOT EXISTS`), если их ещё нет. Отдельный шаг инициализации не требуется.

### Логи

При локальном запуске отдельного лог-файла нет — весь вывод uvicorn идёт в тот же терминал, где выполнена команда запуска.

Помимо стандартных строк uvicorn (`INFO: ...`), в этом же выводе видны теги agent loop из `agent_runtime.py`: `[task]` — полученная задача, `[loop] step N` — номер шага, `[tool] selected/arguments` — вызванный tool и аргументы, `[refusal]` — отказ модели или остановка по `MAX_STEPS`. Секреты в эти теги не попадают.

На VPS используется другой паттерн — вывод перенаправляется в файл (см. ниже, раздел «Запуск на VPS»).

### Остановка и повторный запуск

Локально: `Ctrl+C` в терминале, затем повторно `uvicorn app:app --reload`.

### Запуск на VPS

Проект развёрнут и проверен на реальной VPS (Ubuntu 24.04, Python 3.12.3 — отклонение от целевой ветки 3.13.x зафиксировано и принято, см. `docs/archive/Plan-vps.md`, Шаг 3). Деплой: `git clone`, `venv`, `pip install -r requirements.txt`, `.env` заполнен на сервере, запуск в фоне:
```bash
nohup .venv/bin/uvicorn app:app --host 127.0.0.1 --port 8000 > logs/app.log 2>&1 &
disown
echo $! > app.pid
```
Логи — `tail -n 50 logs/app.log`. Остановка — `kill "$(cat app.pid)"`. Повторный запуск после остановки подтверждён без ошибок (`docs/archive/Plan-vps.md`, Шаг 6).
